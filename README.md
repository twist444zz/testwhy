# MotoBike Parking at BU

เว็บแอปตรวจสอบและจองที่จอดรถ**มอเตอร์ไซค์**ภายในมหาวิทยาลัยกรุงเทพ พร้อมระบบเช็คอิน สะสม และแลกคะแนน ไม่ต้องติดตั้งแพ็กเกจเพิ่ม

## เริ่มใช้งาน

เปิด `index.html` ในเบราว์เซอร์ หรือเปิดโฟลเดอร์นี้ด้วย Live Server

- รหัสผ่าน: `password123`

## สิ่งที่มี

- **แบรนด์:** โลโก้ SVG รวมตัวอักษร BU กับรถมอเตอร์ไซค์ (อยู่ใน `index.html` เป็น `<symbol id="bu-moto-logo">` และ favicon) ธีม Dark & Slate Gray
- **บัญชีผู้ใช้:** สมัคร/เข้าสู่ระบบได้เฉพาะอีเมล `@bumail.net`, รหัสนักศึกษา 10 หลัก, รหัสผ่านอย่างน้อย 8 ตัวอักษร สมัครแล้วเข้าใช้งานทันที (Auto-Login) และบันทึก Session (ติ๊ก "จดจำ" = localStorage, ไม่ติ๊ก = sessionStorage) รหัสผ่านเก็บเป็น SHA-256 + salt
- **หน้าแนะนำการใช้งาน:** เมนู "แนะนำการใช้งาน" ครอบคลุมการสมัคร/เข้าสู่ระบบ ดูโซนว่าง จอง/รายงาน และระบบคะแนน
- **แผนผังลานจอด:** 4 โซน สถานะ ว่าง / ใกล้เต็ม / เต็ม อัปเดตทุก 10 วินาที ซิงก์ข้ามแท็บ พร้อมค้นหา กรอง จอง และเข้าคิวรอ (มีแจ้งเตือนเมื่อมีที่ว่าง)
- **จองที่จอด:** ถือสิทธิ์ 15/20 นาที (30 นาทีเมื่อใช้คูปอง) นับถอยหลังจริง หมดเวลาแล้วหัก Parking Score และคืนช่อง
- **ระบบคะแนน (บันทึกต่อผู้ใช้):**
  - เช็คอินที่จอด +3 คะแนน (โซนละ 1 ครั้ง/วัน, สูงสุด 3 ครั้ง/วัน) และเช็คเอาท์เพื่อคืนช่อง
  - รายงานสถานะ/ปัญหา +5 คะแนน (สูงสุด 3 ครั้ง/วัน)
  - มาถึงตามเวลาที่จอง +2 Parking Score / ไม่มา หรือยกเลิกเมื่อเหลือ < 5 นาที −10
  - แลกสิทธิ์: เพิ่ม Parking Score, ขยายเวลาถือสิทธิ์จอง 30 นาที, คูปองกาแฟ, ส่วนลดล้างรถ พร้อมประวัติคะแนน
- โปรไฟล์ ประวัติการจอด และการแจ้งเตือน

## โครงสร้าง

- `index.html` — โครงหน้าจอและโลโก้
- `styles.css` — ธีม Dark & Slate Gray, responsive
- `app.js` — ตรรกะทั้งหมด การเข้าถึงข้อมูลผ่านอ็อบเจ็กต์ `db` จุดเดียว

## ข้อจำกัดและสิ่งที่ต้องทำก่อนขึ้น production

โปรเจกต์นี้เป็น front-end ล้วน ข้อมูลผู้ใช้ คะแนน และสถานะลานจอดเก็บใน `localStorage` ของเบราว์เซอร์ จึง**ยังไม่ใช่ฐานข้อมูลจริง** และผู้ใช้แก้ไขข้อมูลของตัวเองได้ก่อนนำไปใช้จริงต้องมี:

1. Backend + ฐานข้อมูล (ผู้ใช้ คะแนน การจอง) แทนที่ `db` ใน `app.js` และ hash รหัสผ่านฝั่ง server (bcrypt/argon2), session แบบ HTTP-only cookie
2. ตรวจสอบเจ้าของอีเมล `@bumail.net` จริง (ปัจจุบันตรวจแค่รูปแบบ ไม่ได้ยืนยันว่าเป็นเจ้าของ)
3. ข้อมูลช่องว่างจริงจากเซ็นเซอร์/เจ้าหน้าที่ แทนการจำลองใน `tickZones()`
4. ตรวจสอบการเช็คอินด้วย QR/GPS และตรวจรายงานก่อนให้คะแนน เพื่อกันการปั่นคะแนน
5. เชื่อมร้านพันธมิตรจริงสำหรับคูปองกาแฟ/ล้างรถ (ตอนนี้เป็นรหัสตัวอย่าง)
